# Замер кухни — визуализатор

Планшетный веб-инструмент для замерщиков мебельных компаний: за 5–10 минут на объекте
ввести геометрию помещения, расставить блоки кухни и показать клиенту 3D-концепт.

Это **инструмент визуализации и согласования**, а не CAD-система: чертежи для производства
остаются за конструктором в офисе. Полное описание продукта — в [product.md](docs/product.md),
устройство кода — в [ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что уже работает

- **Отмена и повтор** — кнопки в шапке, `⌘Z` / `⌘⇧Z` на Mac и
  `Ctrl+Z` / `Ctrl+Shift+Z` на Windows (также `Ctrl+Y`). Перетаскивание и жест ползунком
  отменяются одним шагом вместе с зависимыми объектами. Каждый проект хранит до 100
  шагов в памяти до перезагрузки; результат отмены автоматически сохраняется в IndexedDB.
- **План помещения** — рисование замкнутого внешнего контура и внутренних перегородок
  с шагом сетки 10 мм, углами 90° и привязкой к вершинам и середине стены для Т-стыка.
  Пол строится только по внешнему контуру, а стены в 3D стыкуются по общим граням.
  Длина и толщина стены правятся числом в мм;
  масштаб на планшете меняется жестом двумя пальцами.
- **Проёмы и коммуникации** — ПКМ на компьютере или долгое нажатие на планшете открывает
  контекстное меню стены или пола. Окна, двери, вода, газ, розетки и вентиляция крепятся
  к стене, канализацию и другие напольные выводы можно поставить в любой точке пола.
  В 2D и 3D выводы имеют разные условные обозначения и физическую ориентацию.
- **Фасады стен** — на плане можно выбрать стену и открыть именно её внутренний фасад.
  Стрелки переключают стены, а мебель, проёмы и инженерные выводы перемещаются в локальных
  координатах стены независимо от её направления на плане.
- **Каталог блоков** — шкаф напольный, навесной, пенал, столешница, мойка, плита.
  У каждого блока правятся габариты, цвет и положение: X / Y / Z у свободного объекта
  либо смещение вдоль стены и Z у прикреплённого. Геометрия сразу пересчитывается в 2D и 3D.
- **Столешница на ряд** — из свойств напольной тумбы создаётся столешница на весь
  непрерывный ряд, в том числе у свободно стоящей кухни без стен. Она следует за
  добавлением, удалением и изменением тумб, учитывает самую большую глубину и передний
  свес 40 мм. Два перпендикулярных ряда с корректным глухим углом соединяются в одну
  L-образную столешницу; разрыв снова разделяет их. Ряды длиннее 4 м делятся на
  производимые секции по стыкам тумб. Автоподгон можно отключить и продолжить вручную.
- **Автоматический глухой угол** — если перпендикулярная нижняя тумба вплотную закрывает
  край фасада другой, закрытая часть становится неподвижной панелью без ручки, а дверцы
  перестраиваются по доступной ширине. Цоколи соединяются в точке поворота. Связь
  определяется геометрией мебели, не стенами, и исчезает сразу после размыкания стыка.
- **Умная расстановка** — брошенный у стены блок разворачивается по ней и встаёт вплотную,
  однотипные блоки стыкуются без зазора, а попавший на занятое место съезжает в ближайшее
  свободное. Целевая стена подсвечивается зелёным; после установки блок запоминает стену
  и следует за ней при изменении геометрии. Свободные участки рассчитываются по телам всех
  пересекающих стен, включая внутренние Т-стыки; блок не пересекает перегородку при
  автоматической расстановке. Изменение ширины или глубины повторно укладывает блок в ряд. Мебель
  также отталкивается от окна и от сектора открывания двери.
- **Магнит по высоте** — мойка и плита врезаются в столешницу заподлицо, столешница
  садится на тумбы.
- **3D-сцена** — стены с реальными вырезами под окна и двери, пол, инженерные выводы и
  мебель, орбитальная камера. Стена между камерой и комнатой автоматически становится
  полупрозрачной.
- **Инженерные связи** — вода и канализация считаются подключёнными к единственной
  нижней базе-хосту с мойкой, газ — к базе с варочной панелью. Подключённые выводы
  отмечаются зелёным, а отсутствующая
  или несовместимая связь — жёлтым предупреждением, но не геометрической ошибкой.
- **Проверка** — красным подсвечивается блок, вышедший за контур стен или пересекающийся
  с телом любой стены, другим блоком, окном, дверью либо сектором её открывания. Пересекающиеся проёмы и
  выводы за контуром комнаты также подсвечиваются. На плане у наложенных по высоте
  элементов остаётся одна приоритетная подпись, а подпись выбранного блока всегда видна.
- **Экспорт** — кнопка «Скриншот» сохраняет кадр 3D-сцены в PNG.
- **Проекты** — несколько эскизов в IndexedDB: создание, открытие, переименование,
  дублирование и удаление с подтверждением. Изменения сохраняются автоматически;
  текущий проект восстанавливается после перезагрузки. Старое сохранение из localStorage
  переносится при первом запуске и удаляется только после успешной записи.
- **Резервные копии** — экспорт открытого проекта в JSON и импорт копии как нового проекта.
  Данные остаются на этом устройстве; синхронизации между устройствами пока нет.

## Запуск

Нужен Node.js 24.15+ или 26+ и npm. Рекомендуемая CI-версия записана в `.nvmrc`;
при установленном nvm достаточно выполнить `nvm use`.

```bash
npm install
```

```bash
npm run dev
```

Дев-сервер поднимется на http://localhost:5173.

Те же операции доступны короткими командами Make:

```bash
make setup-all
make dev
```

`make help` показывает полный список целей. Для ежедневной проверки достаточно
`make check`, а перед отправкой большой ветки — `make ci` с браузерными тестами.

### Pre-commit

После `npm install` или `make setup` Husky автоматически подключает Git hook. Перед каждым
коммитом `lint-staged` исправляет Oxlint/Prettier только в staged-файлах, после чего
запускаются проверка типов и быстрые Vitest-тесты. Тот же набор можно вызвать вручную:

```bash
make precommit
```

Если hooks не установились, выполните `make setup-hooks`. Аварийно пропустить проверку
можно через `git commit --no-verify`, но обычный рабочий процесс не должен на это опираться.

### Автотесты

Границы слоёв и циклы импортов проверяет `npm run test:architecture` / `make test-architecture`.
Эта проверка входит в обычный `npm test`, pre-commit и CI. Чистая логика запускается в Node,
а интеграционные и UI-тесты — в jsdom.

Быстрый набор проверяет геометрию, проёмы, коммуникации, настенные координаты мебели,
автостолешницы, умную расстановку, валидацию и операции стора, включая загрузку проекта старого формата. Браузерный набор
проверяет перенос старого сохранения, переключение проектов после перезагрузки и наиболее важные сквозные действия: контекстное добавление окна и напольного
вывода, сохранение после перезагрузки, инженерные связи базы с мойкой и переключатель
умной расстановки.

Перед первым браузерным прогоном установите Chromium:

```bash
npx playwright install chromium
```

Для обычной разработки достаточно `npm run check`. Перед отправкой большой функциональной
ветки используйте `npm run check:all`. Те же проверки запускаются в GitHub Actions на
каждый push и pull request.

## Стек

| Слой              | Технология                          |
| ----------------- | ----------------------------------- |
| Сборка            | Vite + TypeScript                   |
| UI                | React 19, Tailwind CSS 4            |
| 2D-редакторы      | Konva через react-konva             |
| 3D                | Three.js + React Three Fiber + drei |
| Состояние         | Zustand                             |
| Проекты           | IndexedDB (без внешней обёртки)     |
| Схемы и валидация | Zod                                 |
| Тесты             | Vitest + Playwright                 |

Бэкенда нет и в этой итерации не планируется — вся логика на клиенте.

> **Версии React зафиксированы на `~19.2` намеренно.** `@react-three/fiber@9` требует
> `react >=19 <19.3`, а `react-konva@19.3` — уже `^19.3`. Совместимая пара — React 19.2
> и `react-konva@~19.2`; при обновлении React эти два пакета нужно двигать вместе.

## Структура

```
src/
├── app/                     # композиция экрана, инструменты, глобальные стили
├── features/
│   ├── plan-editor/          # план, фигуры, хуки инструментов/меню/клавиатуры
│   ├── elevation-editor/     # фасад стены, проекции и фигуры
│   ├── scene-3d/             # сцена, компоненты, параметрические blocks, geometry
│   ├── properties/           # панель и отдельные формы свойств
│   └── furniture-library/    # каталог и его UI
├── application/project/     # store, slices, транзакция, persistence, селекторы
├── domain/
│   ├── model/               # Zod-схемы и типы проекта
│   ├── geometry/            # геометрия комнаты/мебели и пересечения
│   ├── placement/           # магнит, высоты, настенные координаты
│   ├── assemblies/          # угловые соединения и автостолешницы
│   ├── room/                # проёмы и коммуникации
│   └── validation/          # проверки корректности расстановки
└── shared/                  # lib, ui, hooks, canvas; без бизнес-логики
tests/
├── architecture/            # направления импортов, публичные API, циклы
├── unit/                    # чистая логика, структура повторяет src
├── integration/             # команды, транзакции и сохранения
├── ui/                      # React-формы и взаимодействия в jsdom
├── e2e/                     # пользовательские сценарии в Chromium
└── fixtures.ts              # фабрики тестовых данных
docs/architecture-decisions.md # исследование, источники и решения
```

Правила импортов, обоснование структуры и ссылки на изученные рекомендации — в
[архитектурных решениях](docs/architecture-decisions.md).

## Чего пока нет

PWA-обвязка (manifest, service worker), синхронизация между устройствами и серверное
резервирование. IndexedDB хранит данные только в браузере: очистка данных сайта или
потеря устройства удалит проекты, поэтому важные эскизы нужно экспортировать в JSON.
Подробности и порядок работ — в конце
[ARCHITECTURE.md](docs/ARCHITECTURE.md).
