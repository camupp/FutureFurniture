# Архитектура

Документ описывает устройство кода итерации 1 и предназначен в первую очередь как контекст
для ИИ-ассистента: здесь зафиксированы соглашения, системы координат, инварианты и причины
неочевидных решений. Продуктовое описание — в [product.md](product.md).

---

## 1. Границы итерации 1

**Сделано:** 2D-план (стены) → параметрический блок → 3D-визуализация, вид по высоте,
панель свойств, проверка выхода за контур, экспорт кадра, сохранение в localStorage.

**Сознательно отложено:** окна/двери/коммуникации, каталог из 10–15 блоков, пересечения
блоков между собой, Dexie/IndexedDB и список проектов, PWA-обвязка, бэкенд, LLM.

Причина: сначала проверяется сквозной путь «нарисовал → расставил → показал клиенту».
Всё остальное наращивается поверх без переписывания существующих модулей.

---

## 2. Ключевые соглашения

1. **Все линейные размеры в модели — миллиметры, целые.** Перевод в метры (`mmToM`)
   происходит только на границе с Three.js. В Konva миллиметры рисуются напрямую:
   масштаб задаётся трансформом Stage.
2. **2D-план — источник истины для геометрии, 3D — производная.** В 3D нет собственного
   состояния объектов, только чтение стора.
3. **Вся логика на клиенте.** Сетевых вызовов нет вообще.
4. **Доступ к данным только через стор.** Компоненты не читают и не пишут localStorage
   напрямую — это оставляет возможность заменить persist-слой на Dexie без правок в UI.

## 3. Системы координат

Самое частое место ошибок, поэтому разбор подробный.

### План (RoomEditor, Konva)

- `x` — вправо, `y` — **вниз** (как в экранных координатах Konva). Единицы — мм.
- Угол стены: `wallAngle = atan2(dy, dx)`, радианы.
- Поворот блока `rotation` — градусы, положительное значение = по часовой стрелке на экране.
  Konva-свойство `rotation` совпадает с этим напрямую, ничего конвертировать не нужно.
- Матрица поворота в `rotatePoint` — обычная математическая; в системе с осью y вниз она
  визуально даёт вращение по часовой стрелке. `itemFootprint` и Konva согласованы.

### Вид по высоте (ElevationEditor, Konva)

- По горизонтали — ось `x` плана (мм), без изменений.
- По вертикали — высота над полом, но Konva рисует вниз, поэтому **высота `h` лежит на
  координате `y = -h`**. Пол — линия `y = 0`, потолок — `y = -wallHeight`.
- Группа блока позиционируется в `(item.position.x, -item.elevation)`, а прямоугольник
  внутри рисуется от `y = -height` до `y = 0`. То есть локальный ноль группы — низ блока.

### 3D (Three.js)

- Метры. Отображение плана в мир: **`plan.x → world.X`, `plan.y → world.Z`**,
  высота — `world.Y`, пол на `Y = 0`.
- Поворот вокруг вертикали: **`rotation.y = -θ`**, где `θ` — угол из плана в радианах.
  Вывод: `rotation.y = φ` переводит `(1,0,0)` в `(cos φ, 0, -sin φ)`; нужно
  `(cos θ, 0, sin θ)`, следовательно `φ = -θ`. Это касается и стен (`-wallAngle`),
  и блоков (`-degToRad(item.rotation)`).
- Пол строится из `THREE.Shape` по точкам плана и поворачивается на `+π/2` вокруг X
  (именно `+`, иначе план отражается по оси Z), материал — `DoubleSide`, и опущен на
  `y = -0.002`, чтобы не конфликтовать с нижними гранями стен.

## 4. Модель данных (`src/shared/types.ts`)

Типы выводятся из Zod-схем (`z.infer`), то есть схема — единственный источник правды.

```ts
Point = { x, y }                                   // мм, координаты плана
Wall  = { id, start: Point, end: Point, thickness } // толщина 50–500 мм
Room  = { walls: Wall[], wallHeight }               // высота стен 2000–4000 мм

CabinetParams = { width, height, depth, facadeColor }
FurnitureItem = {
  id, type: 'cabinet',
  position: Point,   // центр блока на плане
  elevation: number, // низ блока над полом: 0 — напольный, 1400 — навесной
  rotation: number,  // градусы по часовой; 0 — фасад смотрит в +y
  params: CabinetParams,
}
```

Границы значений вынесены в константы `WALL_LIMITS`, `CABINET_LIMITS`, `ELEVATION_LIMITS`
и используются **одновременно** в Zod-схемах и в `min/max/step` полей ввода — чтобы UI
и валидация не разъезжались.

`elevation` объявлен как `.default(0)`: это даёт обратную совместимость с проектами,
сохранёнными до появления высоты установки. **При добавлении новых полей в схему
используйте `.default(...)`, иначе `merge` при загрузке отбракует весь сохранённый проект.**

### Инварианты

- Стены — **цепочка**: `walls[i].end` совпадает с `walls[i+1].start`. Контур помещения
  (`roomPolygon`) строится как `[walls[0].start, ...walls.map(w => w.end)]`, а дубль
  последней точки отбрасывается, если контур замкнут. Отдельно стоящая стена ломает
  корректность контура — это известное ограничение модели.
- Центр габаритного прямоугольника блока (`bounds(itemFootprint(item)).center`) всегда
  равен `item.position` — блок вращается вокруг собственного центра. На этом построена
  логика перетаскивания в виде по высоте.

## 5. Стор (`src/shared/store.ts`)

Один Zustand-стор со всем состоянием приложения.

**Данные:** `room`, `furniture`.
**UI-состояние:** `selection` (`{kind: 'wall'|'furniture', id}` или `null`), `tool`
(`select | wall | pan`), `orthoSnap`, `viewMode` (`2d | split | 3d`), `editorView`
(`plan | elevation`).

**Действия:** `addWall`, `updateWallLength`, `updateWallThickness`, `removeWall`,
`setWallHeight`, `clearRoom`, `addCabinet`, `moveFurniture`, `elevateFurniture`,
`rotateFurniture`, `updateFurnitureParams`, `removeFurniture`, плюс сеттеры UI.

**Селекторы:** `selectedFurniture`, `selectedWall` — используются как
`useAppStore(selectedFurniture)`.

**Ограничение значений живёт в сторе, а не в компонентах.** `updateFurnitureParams`
зажимает габариты по `CABINET_LIMITS`, `elevateFurniture` — по
`[0, wallHeight − высота блока]`, `rotateFurniture` нормализует угол в `[0, 360)`.
Любой новый ввод можно слать в стор «как есть».

### Сохранение

`persist` с ключом `future-furniture-project`. `partialize` сохраняет только
`room`, `furniture`, `viewMode` — инструменты и выделение при перезагрузке сбрасываются
намеренно. В `merge` сохранённые данные прогоняются через `projectSchema.safeParse`,
и при ошибке берётся состояние по умолчанию: битый localStorage не должен вешать
приложение. Это единственное место, где используется runtime-валидация Zod.

Проект по умолчанию — прямоугольник 3600 × 3000 мм, стены 100 мм, высота 2700 мм,
чтобы приложение не открывалось пустым холстом.

## 6. Модули

| Путь                                   | Ответственность                                             |
| -------------------------------------- | ----------------------------------------------------------- |
| `app/App.tsx`                          | Раскладка, тулбар, переключатели `viewMode` и `editorView`   |
| `modules/room-editor/`                 | 2D-план: сетка, стены, блоки сверху, рисование стен          |
| `modules/elevation-editor/`            | 2D-вид по высоте: разметка высот, перетаскивание по вертикали |
| `modules/scene-3d/`                    | Three.js сцена, посадка камеры, экспорт кадра                |
| `modules/parametric-blocks/Cabinet.tsx`| Геометрия шкафа из параметров                                |
| `modules/furniture-library/`           | Каталог блоков (пока один)                                   |
| `modules/properties/`                  | Панель свойств выделенного объекта                           |
| `modules/validation/rules.ts`          | Правила корректности расстановки                             |
| `shared/utils/geometry.ts`             | Вся планарная математика                                     |
| `shared/utils/useStageViewport.ts`     | Общие зум/панорама для обоих Konva-холстов                   |

### `useStageViewport`

Оба 2D-холста используют один хук: состояние `{scale, x, y}`, `fitTo(points)`,
`zoomBy(factor)`, `handleWheel`, `handleStageDragEnd`. Трансформ вешается на сам `Stage`,
поэтому указатель в миллиметрах берётся функцией `stagePointer(stage)` через
`stage.x() / stage.scaleX()` — так значения корректны и во время перетаскивания холста,
когда позиция Stage меняется мимо React-состояния.

Диапазон масштаба — `0.005…1` px/мм. Толщина линий, размеры подписей и радиусы вершин
компенсируются вручную: `strokeScaleEnabled={false}` для линий и `scaleX/Y = 1/scale`
для `Label`, иначе они масштабируются вместе со сценой.

### RoomEditor

- Инструменты: `select` (выделение и перетаскивание блоков), `wall` (рисование цепочки
  стен), `pan` (панорама холста).
- Привязки при рисовании: сначала к существующей вершине (радиус 14 px в экранных
  единицах, то есть `14 / scale` мм), иначе — ортогональная привязка к предыдущей точке
  при включённом «Углы 90°», затем округление к сетке 10 мм.
- Цепочка завершается по Esc, двойному клику или кликом в первую вершину контура.
- `setWallLength` двигает конец стены вдоль её направления и **сдвигает все последующие
  стены цепочки на ту же дельту**, чтобы контур не разорвался.

### ElevationEditor

- Проекция блоков на плоскость «X плана × высота». Ширина прямоугольника берётся из
  габаритов повёрнутого блока (`bounds(itemFootprint(item)).width`), поэтому для блока,
  развёрнутого на 90°, показывается его глубина — это корректно.
- Блоки сортируются по `y` плана: дальние рисуются первыми.
- Вертикальное перетаскивание ограничено `dragBoundFunc` в экранных координатах:
  `y ∈ [view.y − (wallHeight − height) · scale, view.y]`, то есть блок не проваливается
  под пол и не уходит в потолок.
- Один drag меняет сразу две величины: `position.x` и `elevation`.

### Scene3D

- Посадка камеры (`CameraFit`) выполняется при монтировании и по кнопке
  «Сбросить камеру». Радиус описанной сферы помещения делится на `sin(fov/2)` и на
  `min(1, aspect)` — деление на aspect нужно, чтобы комната влезала и в узкой панели.
- **Эффект посадки камеры не запускается, пока канвас нулевого размера** (`hasSize`):
  при `aspect = 0` расстояние обращается в бесконечность и сцена выглядит пустой.
- `OrbitControls` с `maxPolarAngle = π/2 − 0.05`: камера не опускается ниже горизонта.
- Стена, оказавшаяся между камерой и центром комнаты, плавно уходит в прозрачность
  (`FADED_OPACITY = 0.1`). Сторона определяется знаком скалярного произведения наружной
  нормали стены и вектора «центр стены → камера», пересчёт в `useFrame` с интерполяцией.
  `depthWrite` выключается у прозрачных стен, иначе они перекрывают мебель.
- Свет: ambient + hemisphere + направленный с тенями (`shadow-camera` ±10 м).
- Экспорт кадра: `gl.domElement` кладётся в модульный ref (`screenshot.ts`), у канваса
  включён `preserveDrawingBuffer: true` — без него `toDataURL()` вернул бы пустой кадр.

### Cabinet — параметрическая геометрия

Локальный ноль: центр по ширине, низ блока на `y = 0`, фасад смотрит в `+z`.

Раскладка по глубине `d`: корпус занимает `[-d/2, -d/2 + bodyDepth]`, фасад —
оставшиеся 18 мм до `+d/2`. Число дверей: 2 при ширине > 600 мм, иначе 1; ширина двери
считается с зазором 3 мм. Ручка — брусок 128 мм у открывающегося края.

Цоколь высотой 100 мм существует только при `onFloor` (то есть `elevation === 0`):
поднятый блок трактуется как навесной и цоколя не имеет. Глубина цоколя —
`depth − 50 мм`, то есть его перед утоплен под фасад на 50 мм. Цвет — цвет фасада,
затемнённый до 72%.

### Валидация

Пока одно правило: все четыре угла габаритного прямоугольника блока лежат внутри контура
стен (`pointInPolygon` по полигону центров стен). Если стен меньше трёх — валидация не
применяется. Нарушение подсвечивается красным в плане, в виде по высоте и в 3D.

## 7. Грабли, из-за которых код выглядит именно так

Эти места уже ломались; при рефакторинге их легко вернуть обратно.

1. **`dragEnd` в Konva всплывает.** Перетаскивание блока порождает событие, которое
   доходит до `Stage`. Обработчик панорамы обязан проверять
   `e.target === e.target.getStage()`, иначе смещением вида становятся координаты блока
   и холст «улетает».
2. **Konva не рисует в канвас нулевого размера** (`drawImage ... width or height of 0`).
   Оба редактора монтируют `Stage` только после первого замера контейнера
   (`width > 0 && height > 0`).
3. **R3F на первом кадре может отдать размер 0.** См. `hasSize` в `CameraFit`.
4. **Поля ввода не должны коммитить каждое нажатие.** `NumberField` держит введённый
   текст в локальном `draft` и отправляет значение в стор по blur или Enter (Escape —
   отмена). Иначе стирание числа даёт `Number('') === 0` и блок уезжает в координату 0,
   а промежуточный ввод зажимается по минимуму и мешает набрать число целиком.
5. **Глобальные горячие клавиши обязаны игнорировать поля ввода.** Обработчик
   Delete/Backspace/Escape в `RoomEditor` проверяет `isEditableTarget(e.target)`, иначе
   удаление цифры в панели свойств удаляет сам блок.
6. **Версии React зафиксированы на `~19.2`.** `@react-three/fiber@9` требует
   `react >=19 <19.3`, `react-konva@19.3` — уже `^19.3`; совместимы React 19.2 и
   `react-konva@~19.2`.
7. **Раскладка рассчитана на планшет в альбомной ориентации**: у контейнера
   `min-w-[900px]` и горизонтальная прокрутка. Без этого боковые панели фиксированной
   ширины съедают всё место и холсты схлопываются в ноль.

## 8. Ограничения текущей модели

- Стены — одна цепочка; отдельно стоящая стена искажает контур пола и валидацию.
- Вид по высоте — фронтальная проекция на плоскость X; для блоков у боковых стен он
  показывает их глубину и не различает, у какой именно стены блок стоит.
- Валидация не проверяет пересечения блоков между собой.
- На планшете нет пинч-зума: масштаб только колесом и кнопками.
- Один тип блока (`cabinet`); `FurnitureItem.type` — литерал, при добавлении типов он
  станет объединением, и `FurnitureMesh` / `FurnitureShape` должны будут ветвиться.
