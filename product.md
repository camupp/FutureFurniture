# 🍳 Проект: AI-помощник замерщика для визуализации кухонь

> Консолидированное описание проекта. Максимальный контекст для вайб-кодинга фронтенда.

---

## 1. 🎯 Суть проекта и целевая аудитория

**Продукт:** Планшетный веб-инструмент (PWA) для замерщиков небольших мебельных компаний, которые делают кухни на заказ.

**Боль, которую решаем:** Замерщик приезжает к клиенту, обсуждает проект «на словах», рисует эскиз на бумаге или в лучшем случае в простом редакторе. Клиент не видит, как будет выглядеть кухня, и не может принять решение на месте. Итог — долгие согласования, переделки, потеря времени.

**Решение:** Замерщик за 5–10 минут на планшете вводит геометрию помещения, расставляет параметрические блоки мебели, показывает клиенту 3D-концепт прямо на объекте.

**Ключевое позиционирование:**
- Это **инструмент визуализации и согласования**, а не CAD-система.
- Ответственность за финальные чертежи для производства остаётся на конструкторе в офисе.
- Замерщик — не дизайнер, ему нужен быстрый и интуитивный инструмент.

**Гипотеза MVP:**
> «Замерщик готов использовать планшетный инструмент, если он помогает быстрее согласовать концепцию с клиентом и снижает риск недопонимания, а не заменяет его как специалиста».

---

## 2. 🚫 Что НЕ должен делать MVP

- Точные чертежи для ЧПУ.
- Расчёт стоимости по реальным артикулам.
- Интеграция с 1С/ERP.
- Сложная система прав доступа.
- Поддержка всей мебели мира — только типовые кухонные блоки.
- Фотореалистичный рендер — стилизованный low-poly достаточен.
- Мобильное нативное приложение — только веб (PWA).

## 3. ⛓️ Цепочка данных: от ввода до 3D

### Шаг 1. Ввод геометрии помещения — 2D-редактор

**Не текстом.** Текстовый ввод медленный и неоднозначный. Нужен прямой 2D-редактор на Canvas.

Компоненты:
- **Стены:** пользователь рисует контур. Каждая стена — отрезок с длиной в мм и углом. Углы по умолчанию 90°.
- **Окна и двери:** клик по стене → появляется блок. Ввод ширины, высоты, высоты от пола. Блок можно двигать вдоль стены.
- **Коммуникации (вода, газ, вентиляция):** точки/блоки на плане с координатами (X, Y от угла) и высотой.

**Результат:** структура данных

```ts
type Room = {
  walls: Wall[]        // { start: Point, end: Point, thickness }
  openings: Opening[]  // { wallId, position, width, height, sillHeight, type: 'window'|'door' }
  utilities: Utility[] // { point: Point, height, type: 'water'|'gas'|'vent' }
}
```

**Инструменты:** Konva.js (React-Konva) или Fabric.js. Привязка блока к стене — простая математика на клиенте.

**Продвинутый вариант (для v2):** интеграция с LiDAR на iPad Pro через ARKit/RealityKit. Замерщик «облетает» комнату — получает готовый 2D-план. Это «убийственная» фича второй версии, не MVP.

### Шаг 2. Библиотека параметрических блоков мебели

**Это НЕ Pro100 и НЕ Базис.** Разделяйте понятия:
- **Pro100 / Базис** — производственное проектирование, оперируют деталями (ДСП, кромка), чертежи для ЧПУ.
- **Наш продукт** — визуальная конфигурация, оперирует готовыми блоками, которые «знают» свою внутреннюю структуру.

**Параметрический блок** — единый объект с параметрами:

```ts
type CabinetBlock = {
  type: 'cabinet'
  params: {
    width: number    // 400–1200
    height: number   // 300–2200
    depth: number    // 300–600
    facadeColor: string
    handleType: string
    shelves: number
  }
}
```

Внутри блока «зашита» логика пересчёта. Меняешь ширину 600→800 — дверца и полки пересчитываются, но блок остаётся целым.

**Правила зависимостей:** столешница автоматически «обрезается» под мойку, если их совместить. Пенал не ставится под окно, если высота окна ниже.

**MVP-библиотека: 10–15 блоков, покрывающих 80% типовых кухонь:**
- Шкаф напольный (варьируется ширина/высота/глубина)
- Шкаф навесной
- Пенал
- Столешница (с вырезом под мойку/плиту)
- Мойка
- Плита / варочная панель
- Холодильник (встроенный/отдельностоящий)
- Духовой шкаф
- Барная стойка
- Угловой элемент

**Как не изобретать велосипед:**
- Изучить **c3cad** (параметрическая мебель на Three.js)
- Изучить **boytchev/3d-assets** (набор параметрических объектов)
- Коммерческие API: **Roomle Rubens**, **Planner 5D API**

### Шаг 3. Генерация 3D-визуализации

На основе `Room` + `FurnitureItem[]` строится 3D-сцена. Параметрические блоки мгновенно перестраиваются при изменении параметров. Пользователь может повертеть сцену, показать клиенту.

**Стиль:** low-poly, стилизованный. Не гнаться за фотореализмом — правильная геометрия и понятные пропорции уже дают ценность.

### Шаг 4. Экспорт

- Скриншот через `canvas.toDataURL()`
- Сериализация сцены в JSON
- Экспорт в glTF через `GLTFExporter` (опционально)
- PDF для офиса (на сервере — опционально)

## 4. 💻 Технологический стек

### Обязательно

- **Язык:** TypeScript. Без него Three.js + параметрика превратятся в хаос.
- **Сборка:** Vite
- **Фронтенд:** React
- **2D-редактор:** Konva.js (React-Konva) или Fabric.js
- **3D:** Three.js + React Three Fiber + Drei
- **Состояние:** Zustand (проще Redux, идеален для 3D-состояния)
- **Валидация:** Zod (проверка размеров, блоков, границ)
- **Локальное хранилище:** Dexie.js (обёртка над IndexedDB) — работает офлайн

### Бэкенд — минимальный слой

**Для чистого конструктора без ИИ и облака — не нужен вообще.**

**Когда понадобится:**

1. **Прокси для LLM** — ключи YandexGPT/GigaChat нельзя светить на клиенте. Решение: Cloudflare Workers или Vercel Edge Function (20 строк).
2. **Сохранение в облаке** — Supabase или Firebase (Auth + PostgreSQL + Storage из коробки).
3. **Аутентификация и роли** — компания / замерщик / конструктор. Закрывается Supabase.
4. **PDF-генерация** — серверный рендеринг надёжнее.
5. **Аналитика** — события через простой API или Supabase.

### Деплой

- Фронтенд: Vercel или Netlify
- Прокси: Cloudflare Workers

### Рекомендуемый стартовый стек для вайб-кодинга

```
React + Vite + TypeScript
├── Zustand          — состояние
├── React-Konva      — 2D-редактор помещения
├── React Three Fiber + Drei — 3D-сцена
├── Zod              — валидация
├── Dexie.js         — IndexedDB (офлайн-сохранение)
└── Tailwind CSS     — UI (опционально, но ускоряет)
```

## 5. 🧩 Подпроекты / модули MVP

Разбейте фронтенд на изолированные модули. Каждый можно вайб-кодить отдельно.

### Модуль 1: RoomEditor (2D)

- Холст Konva с сеткой в мм
- Инструменты: добавить стену, окно, дверь, коммуникацию
- Свойства выбранного объекта в правой панели
- Валидация: стены не пересекаются, окно не выходит за стену
- Экспорт: `Room` object

### Модуль 2: FurnitureLibrary (каталог блоков)

- Панель с превью блоков (можно генерировать мини-3D или SVG-иконки)
- Категории: напольные, навесные, техника, декор
- При выборе — блок добавляется в сцену

### Модуль 3: Scene3D (3D-вьюпорт)

- Three.js сцена с камерой OrbitControls
- Рендер стен из `Room`
- Рендер блоков из `FurnitureItem[]`
- Параметрические компоненты блоков (`<Cabinet />`, `<Countertop />`, `<Sink />`)
- Панель свойств выбранного блока

### Модуль 4: StateStore (Zustand)

- `room: Room`
- `furniture: FurnitureItem[]`
- `selectedId: string | null`
- `camera: { position, target }`
- Экшены: `addWall`, `addFurniture`, `updateFurnitureParams`, `removeFurniture`

### Модуль 5: ParametricBlocks (библиотека React-компонентов)

Каждый блок — отдельный React-компонент на Three.js:

```tsx
<Cabinet width={600} height={800} depth={550} color="#D2B48C" />
<Countertop length={2400} depth={600} hasSinkCutout={true} />
```

Внутри — геометрия из примитивов (`boxGeometry`, `cylinderGeometry`).

### Модуль 6: ValidationLayer

- Проверка: блок не выходит за стены
- Проверка: блок не пересекается с другим блоком
- Проверка: пенал не стоит под окном ниже его высоты
- Проверка: блок не перекрывает коммуникации

### Модуль 7: Persistence

- Сохранение/загрузка проекта через Dexie.js
- Список проектов
- Экспорт JSON

### Модуль 8 (v2): AI Dialog

- Чат-интерфейс
- LLM-прокси через Cloudflare Workers
- Парсинг ответов → обновление `Room` / `FurnitureItem[]`

## 6. 📊 Метрики успеха MVP

**Продуктовые:**

- Время от начала замера до готового эскиза ≤ 10 минут
- >70% замерщиков используют инструмент повторно в течение недели
- >80% клиентов говорят, что эскиз помог понять результат
- 3–5 мебельных компаний готовы тестировать на своих замерщиках

**Технические:**

- Отклик интерфейса ≤ 100 мс
- Генерация/перестроение 3D-сцены ≤ 1 с
- Ноль критических ошибок (мебель в стене, перекрытие прохода) на 20 тестовых сценариях

## 8. ⚠️ Главные риски и как обойти

| Риск | Решение |
|------|---------|
| «Замерщику некогда учиться» | Интерфейс интуитивный, обучение ≤ 15 мин. Показать экономию времени, а не новую работу. |
| «Планшет неудобен на объекте» | Офлайн-режим + синхронизация. Крупные кнопки, ввод пальцем. |
| «Клиент не воспримет эскиз всерьёз» | Стилизованный, но опрятный рендер. Правильные пропорции, тени, текстуры. |
| «ИИ не понимает размеры» | Обязательные поля для габаритов. Валидация на бэкенде. В MVP — без свободного текста. |
| «Дорого вызывать LLM» | Кэш типовых ответов, локальная модель для простого, GPT только для сложного. |
| «Мебельщики не доверяют» | Позиционировать как «черновик за 5 минут», а не замену дизайнера. |

## 10. 🧠 Ключевые концепции, которые важно держать в голове

1. **2D-редактор — это источник истины для геометрии.** 3D — производная.
2. **Параметрический блок — единый объект с параметрами**, не набор деталей.
3. **Вся логика — на клиенте.** Бэкенд — только прокси и синхронизация.
4. **MVP без ИИ.** Сначала проверьте ценность конструктора. LLM добавляйте во вторую итерацию.
5. **Low-poly > фотореализм.** Правильная геометрия важнее красивых текстур.
6. **Замерщик — не дизайнер.** Интерфейс должен быть понятен за 15 минут.
7. **Офлайн-режим обязателен.** На объектах часто нет нормального интернета.

## 11. 🎬 С чего начать завтра

1. Найдите 3–5 замерщиков из небольших мебельных компаний. Проведите 15–20-минутные интервью. Вопросы:
   - «Покажите, как вы сейчас делаете эскиз на замере?»
   - «Что самое раздражающее в этом процессе?»
   - «Если бы был планшетный инструмент, делающий эскиз за 5 минут, что бы это изменило?»
2. По результатам — зафиксируйте **один сценарий использования** и начинайте вайб-кодить `RoomEditor` (Модуль 1).
3. Не пишите бэкенд. Всё локально через Dexie.js.
4. Когда RoomEditor готов — добавьте Scene3D и **один** параметрический блок (шкаф). Покажите замерщикам.
